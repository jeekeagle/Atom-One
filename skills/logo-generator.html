PART 01
定位与功能
它不是一个「画图提示词」，而是一条从需求采集到规范归档的完整链路。 这一部分是判断要不要用它的依据：它替换了什么、能做什么、边界在哪。
1.1 · 定位

它解决什么，替代什么

替换的旧做法
「找设计师做一个 logo」
— 一次沟通往返、一轮报价、一份孤立文件
  • 需求靠嘴述对齐，元素取舍全凭对方经验
  • 交付一张 PNG，尺寸、配色、深底用法全靠猜
  • 没有规范，半年后没人知道该怎么用
本 skill 的做法
一句话需求 →
六套方案 + 规范手册 + 可维护源码
  • 先出 6 套差异化方向，用选代替猜
  • 产出是矢量 + 多尺寸位图 + 品牌规范，不是单张图
  • 参数写在数据源里，改配色不用重画
1.2 · 功能清单

八项能力，各自做到什么程度

01需求采集四问定调：品牌名 / 行业 / 核心概念 / 风格偏好，逐轮收敛
02图案生成按四大基本元素 + 四种组合 + 字母抽象，出 ≥6 套差异化 SVG
03交互预览网格预览页，逐个展示并附设计理由，便于横向比较
04迭代精修从 6 套收窄到 2–3 套，支持改参数、换色、合并元素
05多格式导出SVG 矢量 + 1024/512 PNG + favicon 三档 + 深底反白版
06品牌规范手册六章 A4 手册，几何数值全部从 SVG 解析，不手写
07对比度审计全色 / 反白 / 单色三态同时算 WCAG 比值，超标即不合格
08动态背景6 套 GLSL 着色器，真实标志注入并按明暗自动取前景色
第 05–08 项是自己加的。基础 skill 只做到「出一张好看的图」； 扩展后补上导出、规范、审计、动态四环 —— 这四步决定成品能不能进真实项目。
1.3 · 适用边界

什么该用它，什么不该用

适用几何抽象型标志
  • 科技、SaaS、工具类产品的抽象符号与产品图标
  • 需要在 favicon 尺寸下仍然清晰的单色标志
  • 需要同时交付官网、名片、PPT、App 图标的一致视觉
  • 要一份能交给第三方执行、不会走样的规范文档
  • 需要动态展示：官网 Hero、发布会开场、产品录屏
不适用超出矢量几何表达力
  • 需要复杂插画、人物、场景的形象标志
  • 必须严格贴合既有品牌系统的补充设计
  • 中文文字型标志 —— 字体转曲后不可编辑、不可搜索
  • 需要像素级精修的写实 / 拟物 / 3D 渲染风格
  • 只想要一张图就发朋友圈 —— 用不着走完七个阶段
一条判断标准：问自己「这个标志的核心形状，能用几个几何元素在 100×100 的格子里说清吗？」 能，就交给它；不能，说明你要的是插画，不是几何标志。
PART 02
实现逻辑
这个 skill 不是一段提示词，而是一个目录里的四类东西在配合工作： 规则文件决定「做成什么样」，样式资源决定「长什么样」， 脚本负责「算出来」，参考文档负责「凭哪条依据」。
2.1 · 工作流程

七个阶段：输入 → 动作 → 输出

PHASE 1
信息采集
输入 品牌名 · 行业 · 核心概念 · 风格偏好 → 动作 四问定调 → 输出 一份创作简报
PHASE 2
图案生成
输入 创作简报 + 图案库规则 → 动作 匹配类型、产出 ≥6 套 → 输出 SVG 文件 + 交互预览页
PHASE 3
迭代精修
输入 用户的取舍意见 → 动作 定向改参数、合并元素、换配色 → 输出 收窄后的 2–3 套
PHASE 4
精品展示图
输入 选定的 SVG → 动作 转 PNG、调 Gemini 生成背景 → 输出 4 张展示图 · 需 API Key
PHASE 5
交付
输入 定稿标志 → 动作 导出矢量与位图 → 输出 预览页 + SVG + 多档 PNG
PHASE 6
品牌规范
输入 定稿 SVG → 动作 解析几何、写六章手册、跑对比度 → 输出 A4 规范手册 HTML + PDF
PHASE 7
动态背景
输入 标志 SVG → 动作 注入 6 套着色器并判明暗 → 输出 可全屏交互的 WebGL 页面
2.2 · 关键机制（一）

决定成品质量的六条硬规则：审美

前四条管「好不好看」，来自对上百个参考标志的归纳；后两条管「会不会出错」，来自实战踩坑。

R1极致简化
核心元素 1–2 个，总数不超过 5–6 个。
违反后果：网格铺满 → 没有视觉焦点，缩小即糊成一团。
R2慷慨留白
画布 40–50% 必须是空的。
违反后果：元素挤在一起 → 失忆、失去呼吸感。
R3精确比例
线宽 2.5–4，点半径 2–8，间距 ≥8–12（viewBox 100×100 下）。
违反后果：线太细显弱、太粗显笨拙；两者都不专业。
R4刻意不对称
完美对称是无聊的，要引入有意的视觉失衡。
违反后果：居中对称 → 呆板、无能量、无记忆点。
R5克制胜于装饰
每个元素都要能解释存在理由，不加多余渐变与阴影。
违反后果：靠效果堆砌 → 显得廉价，且缩小后完全垮掉。
R6负空间圆角切口
做挖空时开口必须是圆角，不能是尖角。
违反后果：尖角切口 → 显得生硬、像没做完。
这六条是「先看这一页」的硬约束。design_patterns.md 把它放在 Part 0「READ THIS FIRST」， 排在所有图案类型之前 —— 因为它们决定的是成品的天花板， 而后面的图案库只是在这个天花板下提供可选项。
2.3 · 关键机制（二）

决定成品质量的四条硬规则：技术

这一组不关乎审美，关乎「会不会静悄悄地坏掉」。违反后往往不报错，只是结果不对。

R7几何必须解析，不能手写
规范里的每个数值都要由脚本从 SVG 的 points / radius / stroke-width 反推。
违反后果：规格与资产漂移 —— 比没有规格更糟，因为第三方会照着错的做。
R8SVG 默认填充是黑色
任何 <polygon> / <path> 必须显式写 fill="none"。
违反后果：漏写即渲染成一坨实心黑块，且没有任何提示。
R9JS 注入字符串必须带引号
textContent = #1A1A1A; 是语法错误。
违反后果：整段脚本静默失效，所有动态数值变成「—」，页面看着像正常但内容全空。
R10对比度必须三态同审
全色 / 反白 / 单色三种渲染同时算 WCAG 相对亮度比值。
违反后果：只看「全色压白底」会漏判 —— 深色主色在深底必然不可用，而反白版恰恰是它的标准用法。
这四条共同的特征是：违反后不抛异常。它们不会让程序失败，只会让产物悄悄走样。 所以必须写成规则写进 SKILL.md，让执行者每次都主动检查，而不是靠 debug 发现。
2.4 · 架构分层

四层结构，各管一段

规则层RULE
SKILL.md 定义七个阶段与每阶段的产出要求；references/ 存图案库、背景风格、WebGL 实现依据。决定「做成什么样」。
SKILL.md
references/*.md
资源层ASSET
showcase_template.html 提供预览页骨架；background_library.html 内联 6 套 GLSL 着色器与自适应配色。决定「长什么样」。
assets/*.html
计算层SCRIPT
四个 Python 脚本负责位图导出、展示图生成、动态背景组装与 Key 体检；负责「算出来」，不负责决策。
scripts/*.py
产物层OUTPUT
最终落地为可编辑矢量、多档位图、交互预览页与品牌规范手册，每一项都有独立目录与命名规范。
svg/ png/ icons/
preview.html
brand_guide.pdf
依赖方向
规则层 → 资源层 → 计算层 → 产物层，单向依赖。 脚本不读规则、规则不读脚本，改任一层不会波及其它层。
可移植性
整个目录可整体拷贝到另一台机器。Windows 差异被收敛进 runtime/bin 与 .pth 两处，不散落在代码里。
改哪一层
想改审美标准 → 改规则层；想改外观 → 改资源层； 想改产物形式 → 改计算层。先判断改哪一层，再动手。
2.5 · 技术要点

文件结构与单一数据源

目录结构
# skill 本体 logo-generator/ ├── SKILL.md # 七阶段规则 ├── requirements.txt # Python 依赖 ├── .env.example # Key 模板 ├── references/ │ ├── design_patterns.md │ ├── background_styles.md │ └── webgl_backgrounds.md ├── assets/ │ ├── showcase_template.html │ └── background_library.html ├── scripts/ │ ├── svg_to_png.py │ ├── generate_showcase.py │ ├── generate_showcase_webpage.py │ └── setup_gemini_key.py └── runtime/bin/ # Windows cairo DLL
单一数据源架构
样式与配色不写死在生成脚本里，而是拆成两个数据文件：
styles.py # 10 种结构定义 palettes.py # 10 套配色定义 build_variants.py # 组合生成
结果：10 结构 × 10 配色 = 100 组。 改配色只动 palettes.py， 改结构只动 styles.py， 两者互不干扰，也不用重画任何一张图。
为什么重要
把「结构」和「配色」解耦后，一个 logo 体系才真正具备可维护性： 客户要换品牌色，改一个文件重跑即可，不需要回到设计环节。
2.6 · 技术要点

渲染方式与适配策略

矢量渲染
cairosvg
全部标志以 viewBox 0 0 100 100 的 SVG 为唯一真源， 位图由 SVG 导出而来。矢量是源头，PNG 只是派生物 —— 改设计永远改源头。
Windows 上 pip 装不上原生 cairo，已内置 12 个 DLL 并用 .pth 双层注入 PATH。
颜色适配
currentColor
SVG 内部不写死颜色，统一用 currentColor。 同一份文件换父级 color 即整体变色，无需重新生成。
深底反白版、单色版由此自动派生：换 context 即得第三种渲染态。
尺寸适配
三档下限
每个变体都测出最小可用尺寸：全色 / 实心 / 单色 / 锁定组合各一条。 低于这个值说明哪部分结构糊了。
导出档位固定为 1024 / 512，favicon 为 16 / 32 / 48。

四种渲染态 × 文件 × 用途

渲染态文件用途
全色SVG（currentColor）+ PNG 1024 / 512官网、印刷物料、社交媒体
反白深底专用 SVG 与 PNG 各一套深色背景、影棚、屏幕
单色纯黑版本传真、烫印、单色印刷
应用图标favicon 16 / 32 / 48 + 512浏览器标签、App 图标
一条贯穿性原则：结构唯一，颜色派生。 任何时候只维护一份几何，颜色与尺寸都是它的投影 —— 客户换品牌色，改一个文件重跑，不需要回到设计环节。

使用方式

3.1 · 安装与调用

装进目录，一句话启动

安装位置
~/.workbuddy/skills/logo-generator/
放入用户级 skill 目录即可跨项目生效；若走市场安装，用 search_and_install_skills 先搜后装，名称须与搜索结果完全一致。

Python 依赖（仅 Phase 4 需要）

python -m pip install -i https://pypi.org/simple \ -r requirements.txt # cairosvg · python-dotenv · google-genai # Pillow · svglib · reportlab
调用方式 · 触发词
「为我的产品设计一个 logo」
「帮我做一套品牌标志」
命中 skill 的描述语义即自动加载，无需手动指定路径。
直接跑脚本
python scripts/svg_to_png.py logo.svg \ --width 1024 --height 1024 python scripts/generate_showcase_webpage.py \ --logo logo.svg \ --title "Brand — WebGL Showcase" \ -o showcase.html
Key 不是必需品。Phase 1–3 完全离线跑得通； 只有 Phase 4 生成精品背景图才需要 Gemini Key。
3.2 · 操作步骤

从一句话到拿到成品

STEP 01
给四要素
品牌名 · 行业 · 核心概念 · 风格偏好。缺哪个补哪个，不用一次说完。
STEP 02
看预览页选方向
打开交互预览页横向比较，选出 2–3 套最接近的。选定之前不必提修改意见。
STEP 03
提修改意见
说清是「留白不够」「线条太粗」还是「颜色不对」。定向改，不整体重生成。
STEP 04
确认定稿
锁定一套，导出矢量与多档位图，并同步生成品牌规范手册。
STEP 05
补做展示图
可选。配置 Key 后生成 4 张背景展示图，用于提案、官网 Hero 与社交媒体。
STEP 06
交付与归档
预览页 + SVG + PNG + 规范手册打包。规范手册随包走，第三方才不会用错。
整条路径里只有 STEP 02 需要你做真正的决策 —— 选哪套。 其余五步都是执行。STEP 03 的反馈越具体（「线条太粗」优于「不够好看」）， 改动越准；STEP 04 之后才动手改结构，避免白做。

3.4 · 常见问题（一）

前提、依赖与容易踩的坑

前提与依赖
  • Phase 1–3 零外部依赖：不需要 API Key，不需要网络，不调用任何模型。产出完整标志体系无障碍。
  • Phase 4 需要两样：Google Gemini API Key（免费层即可）+ 能连到 Google 的本地代理端口。
  • Windows 需原生 cairo：pip 装不上，已内置 DLL 并用 .pth 注入。换 Python 解释器需重放 .pth。
  • 内置 DLL 不可升级：zlib / freetype / expat 换新版会导致 cairo 加载失败（error 0x7e）。

五个实战踩坑

#现象根因与解法
01多六边形横穿成乱线多个坐标点并入单个 <polygon> 会自动连线 —— 改用多段闭合子路径的 <path>
02字标上下颠倒字体轮廓转曲时需做 y 翻转，用 fontTools 官方 Pen 处理坐标
03模板改了没生效模板与产物同名会被静默回滚 —— 模板存 .tpl.html，产物存 .html
04环境代理连不上 Google环境变量默认端口对 Google 返 502 —— 必须实测哪个端口真能通，不能信环境变量
05第三方接口直接崩SDK 大版本改了字段名：api_endpoint → base_url
3.5 · 常见问题（二）

报错对照表与边界提醒

报错对照表
现象处理
API key not valid复制时带了空格换行，或用了别的项目的 key；跑体检脚本可精确定位
unregistered callers请求没带 key，检查 .env 是否被读到了
location not supported地区不受支持或代理出口在受限地区，换代理节点
Model not found模型 ID 已下线，跑体检脚本看当前可用清单

PNG 导出失败确认 cairosvg 可导入；换解释器需重放 .pth
边界提醒
免费层数据可能被人工阅读。Google 明确提示免费层数据用于改进产品，审核员可能查看 —— 不要把敏感信息送进去。
限额不公开固定表。Google 不公布各模型的具体额度，以 AI Studio 界面显示为准，别照搬旧文档。
Key 关闭页面后不可再见。只能删除重建 —— 拿到后立刻写进 .env。
规范手册的价值高于图本身。没有规范，标志离开设计者就不再可控；有了规范，换人执行也不会走样。
